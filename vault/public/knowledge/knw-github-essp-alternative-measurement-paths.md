Source: `vault/public/assets/2025-05-28-GitHub-ESSP-Ebook-EZ-Version012.pdf`, pages 31-32.

GitHub includes alternatives for organizations that are not ready to run the full ESSP. The lightest path is to focus on feature-usage telemetry and developer feedback, which gives closer-to-code insight with less analytics investment and without claiming strong downstream causality.

A second path is business value engineering oriented around delay, cost, and risk reduction. GitHub presents this as useful when the organization wants to reason about Copilot or other changes in explicitly economic terms and connect usage with value outcomes.

The third path is to use SPACE as the foundation for a custom framework. In that mode, the goal is still to preserve a holistic, research-backed view of engineering work while choosing metrics and interventions that better fit local context than the ESSP defaults.
